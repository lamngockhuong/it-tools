# Pre-built Deployment Strategy

This document explains how to deploy pre-built files to GitHub Pages, avoiding timeout issues.

## 🎯 Strategy Overview

Instead of building on GitHub Actions (which can timeout), we:

1. **Build locally** to `dist/` folder
2. **Prerender** HTML files in `dist/`
3. **Copy `dist/` to `prerendered/`** for git tracking
4. **Commit the prerendered/ folder** (tracked in git)
5. **Deploy via GitHub Actions** from `prerendered/` (just uploads, no build)

**Key difference**: The `prerendered/` folder is a **copy of `dist/`** specifically for deployment. The `dist/` folder remains gitignored.

## 🚀 Quick Start

### Step 1: Build Locally

Run the interactive build script:

```bash
pnpm build:github
```

This script will:

- Generate routes and sitemap
- Build the application to `dist/`
- Start preview server
- Ask you how many pages to prerender
- Run prerendering (updates HTML in `dist/`)
- Copy `dist/` to `prerendered/` for deployment
- Show next steps

### Step 2: Choose Prerender Option

When prompted, select:

- **Option 1**: All 377 pages (~8-10 minutes) - Best SEO
- **Option 2**: Top 100 pages (~3-5 minutes) - Good balance
- **Option 3**: Top 50 pages (~2-3 minutes) - Quick with SEO
- **Option 4**: Top 25 pages (~1-2 minutes) - Minimal
- **Option 5**: Skip prerendering - SPA only

### Step 3: Commit prerendered/ Folder

```bash
# The prerendered/ folder is tracked in git (not gitignored)
git add prerendered/

# Commit
git commit -m "chore: build for deployment"

# Push
git push
```

### Step 4: Deploy via GitHub Actions

1. Go to your GitHub repository
2. Click **Actions** tab
3. Select **Deploy Pre-built Files** workflow
4. Click **Run workflow**
5. Wait ~1-2 minutes for deployment

## 📋 Manual Build Commands

If you prefer manual control:

```bash
# Set base URL
export SITEMAP_BASE_URL="https://it-tools.khuong.dev"

# Generate routes
pnpm script:generate:routes

# Generate sitemap
pnpm generate:sitemap

# Build to dist/
pnpm build

# Copy assets to dist/
cp dist/index.html dist/404.html
cp public/sitemap.xml dist/sitemap.xml
cp public/robots.txt dist/robots.txt

# Start preview server
pnpm preview &

# Prerender (with options) - updates HTML in dist/
export PRERENDER_MAX_PAGES=100             # Top 100 pages
export PRERENDER_CONCURRENCY=15            # 15 pages in parallel
export PRERENDER_WAIT_TIME=1000            # 1 second wait
pnpm prerender

# Kill preview server
killall node

# Copy dist/ to prerendered/ for deployment
rm -rf prerendered/*
cp -r dist/* prerendered/
```

## 🎛️ Environment Variables

Control prerendering behavior:

| Variable                | Default | Description                       |
| ----------------------- | ------- | --------------------------------- |
| `PRERENDER_MAX_PAGES`   | `0`     | Max pages (0 = all)               |
| `PRERENDER_CONCURRENCY` | `10`    | Parallel pages (5-10 recommended) |
| `PRERENDER_WAIT_TIME`   | `1500`  | Wait time (ms)                    |
| `SITEMAP_BASE_URL`      | -       | Base URL for sitemap              |

**Note**: `PRERENDER_OUTPUT_DIR` is not needed - prerendering always outputs to `dist/`, then we copy to `prerendered/`.

**⚠️ Concurrency Warning**: Values higher than 10 may cause timeout errors as the preview server gets overloaded. Stick to 5-10 for reliability.

## ⚠️ Important Notes

### prerendered/ vs dist/

**dist/ folder**:

- Generated by `pnpm build`
- Contains build output
- **Prerendering updates HTML here**
- **Always gitignored**
- Not committed to repository

**prerendered/ folder**:

- **Copy of dist/** after prerendering
- **Tracked in git** (not gitignored)
- Committed to repository
- Used for GitHub Pages deployment

### Workflow

The workflow is: `build → dist/ → prerender (updates dist/) → copy to prerendered/ → commit → deploy`

## 🔄 Updating Deployment

When you need to update:

```bash
# 1. Clean old build (optional)
rm -rf prerendered/

# 2. Build again
pnpm build:github

# 3. Commit and push
git add prerendered/
git commit -m "chore: update build"
git push

# 4. Re-run GitHub Actions workflow
```

## 🆚 Comparison with Other Methods

| Method                   | Build Time      | GitHub Actions Time | Pros                                             | Cons                                   |
| ------------------------ | --------------- | ------------------- | ------------------------------------------------ | -------------------------------------- |
| **Pre-built (This)**     | ~5-10 min local | ~1-2 min            | No timeout, full control, dist/ stays gitignored | Need local build, prerendered/ in repo |
| **GitHub Actions Build** | -               | ~8-15 min           | Automated                                        | May timeout, uses Actions minutes      |
| **Fast Deploy**          | -               | ~2-3 min            | Quick                                            | No prerendering, worse SEO             |

## 💡 Best Practices

1. **Build locally** when you have good internet and time
2. **Use Option 2 or 3** (50-100 pages) for good balance
3. **Test locally** before committing: `pnpm preview` and check pages
4. **Commit prerendered/** regularly for deployment
5. **Keep dist/** gitignored - never commit it

## 🐛 Troubleshooting

### prerendered/ folder not found

```bash
# Make sure to run the build script first
pnpm build:github
```

### Prerender fails locally

```bash
# Check if preview server is running
curl http://localhost:4173

# Kill any hanging processes
killall node

# Try again
pnpm build:github
```

### GitHub Actions fails

Check that:

- `prerendered/` folder exists in repository
- `prerendered/` contains `index.html` and tool pages
- Workflow file is present: `.github/workflows/deploy-prebuilt.yml`

### Repository size concerns

The `prerendered/` folder will add ~50-100MB to your repository. This is acceptable for most GitHub repositories.

Benefits:

- `dist/` stays gitignored (cleaner git history)
- `prerendered/` only updated when deploying
- Clear separation between build artifacts and deployment files

## 🎯 Recommended Workflow

**For production releases:**

```bash
pnpm build:github  # Choose Option 2 (100 pages)
git add prerendered/
git commit -m "chore: build for production deployment"
git push
# Deploy via GitHub Actions
```

**For quick updates:**

```bash
pnpm build:github  # Choose Option 4 (25 pages) or 5 (skip)
git add prerendered/
git commit -m "chore: quick build for deployment"
git push
# Deploy via GitHub Actions
```

## 📊 Expected Sizes

- **prerendered/ folder**: ~50-100 MB (with prerendering)
- **dist/ folder**: ~50-100 MB (never committed, gitignored)
